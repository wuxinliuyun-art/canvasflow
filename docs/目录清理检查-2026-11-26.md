# CanvasFlow 目录清理检查

检查日期：2026-11-26。只读检查原有文件，没有删除或移动任何内容。体积按文件长度汇总，GB 按 1024 MB 换算，不含文件系统额外占用。

## 优先清理候选：约 7.10 GB

| 路径（相对项目根目录） | 大小 | 判断 |
| --- | ---: | --- |
| `.codex-build/` | 5880.70 MB | 大量历史验证构建、重复 publish、NuGet 下载包和测试输出；不属于正式源码。若需保留独立下载包可先归档。 |
| `.codex-tmp/` | 173.35 MB | comfy-build 临时编译及测试日志；测试可能再次创建该目录。 |
| `artifact-build/` | 405.67 MB | 历史 Electron 安装包与 win-unpacked。 |
| `final-build/` | 405.68 MB | 历史 Electron 安装包与 win-unpacked。 |
| `release-build/` | 405.67 MB | 历史 Electron 安装包与 win-unpacked。 |

这三份旧打包目录结构相似，但本次未逐文件计算哈希，不宣称三份内容完全相同。当前 package.json、SOURCE_SETUP.md、build-dotnet.cmd 和安装器使用 .NET 发布流程，安装包输出指向 dist-dotnet。

清理以上候选前应关闭相关构建、测试及从这些目录启动的程序；不要依据目录名批量删除其他位置的同名目录。

## 能重建，但并非无用垃圾

- `desktop-dotnet/bin` 约 1208 MB，`obj` 约 2 MB：桌面编译产物。启动 BAT 会使用 Debug 下的 EXE；清理后需要重新构建，不应在程序运行中删除。
- `background-removal-worker/bin` 与 `obj` 合计约 412 MB：抠图工作进程构建产物；只清理这两个子目录，不要删除工作进程源码目录。
- `node_modules/` 约 405 MB：项目依赖；清理后需要 npm ci 恢复，开发构建可能受影响。
- `integrations/` 约 140 MB：含 MCP 集成源码与产物，不能整目录删除；本次未逐项确认客户端实际启动路径。
- `.opencode/` 约 55 MB：含 node_modules、plans、skills；保留配置、计划和技能，是否移除依赖取决于是否还使用 OpenCode。

## 不建议当垃圾清理

- `data/` 约 792 MB：含素材、插件、WebView2 用户环境、画布状态、设置和凭据等。不要删除整个目录，也不要把其中的 secrets.json 发给他人。
- `projects/` 约 112 MB：项目文件。
- `download/` 约 98 MB：下载素材和视频等，可能被项目引用。
- `export/` 约 197 MB：用户导出成果。发布包要求 export 为空，不代表源码工作目录的成果应被清空。
- `extensions-presets/` 约 587 MB：拓展脚本、工具及依赖，不能按体积删除；input/output 内文件也可能是待取回结果。
- `.git/` 约 338 MB：版本历史及恢复依据。
- `assets/`、`modules/`、源码、tests、docs、构建脚本与安装器：本次没有足够证据认定为无用文件。

## 建议顺序

先处理第一组约 7.10 GB 的历史构建产物。再人工挑选 tmp、dist 和旧安装包。暂不动项目数据、拓展、依赖和当前桌面构建目录。

本次未启动浏览器、未操作画布、未修改源码、未执行删除，也未进行逐文件去重或运行中进程依赖验证。
