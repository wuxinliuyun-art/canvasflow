# 导出文件与卸载保留规则

- `export/ai_generated` 是生成结果的输出目录；截图任务也写这里，不要求进入画布素材仓库。用户选择的自定义导出目录同样属于用户数据。
- `data/assets/generated` 是画布引用的生成图素材，并非所有生成任务的完整备份。同内容素材按 SHA-256 去重；已有同内容素材可能复用 `originals` 中的记录。不得用这个目录的文件数量推断生成结果总数。
- PPT 等拓展结果可能同时存在于拓展的 `output` 与用户配置的导出目录。拓展 `output` 可能被下一次运行清理，导出副本必须独立保留。
- Windows 安装器仅按安装记录卸载程序文件，不得递归删除整个 `app`，也不得通过根目录 `*.json` 等通配符或整目录清理误删用户文件。旧版 `app/export`、`data`、`download`、`projects` 和拓展目录均应保留。覆盖安装仅清理保留给前端的 JS/HTML/CSS/modules 资源。
- 发布时排除用户数据和导出内容，保留空 `export` 目录；安装器不应把导出文件登记为可卸载程序文件。
- `/api/save-export-files` 在 Windows 桌面与 Node 服务两侧均以独占创建方式保存文件，同名自动加 ` (1)`、` (2)`，不覆盖已有内容。接口返回真实保存路径，调用方应使用它定位文件。此规则也适用于通过该接口导出的项目 JSON；独立的自动备份接口不受影响。

本次验证：Windows 项目编译通过；桌面保存函数对中文嵌套路径、图片/PPT/JSON 分别进行 16 个并发同名写入，原文件和全部新文件均保留；Node 保存函数验证同名输出与错误透传。未在正式安装目录执行安装或卸载。

## 生成图片命名与哈希

- 新生成图的导出名和 Windows `data/assets/generated` 素材名采用 `yyMMdd-项目名称-序号`，例如 `261015-产品设计-001.png`。素材名按当日项目分配可用序号，独占创建防止并发覆盖；同内容素材继续去重，不要求两处序号完全一致。
- 素材索引继续使用原始图片字节的 SHA-256 作为内部 ID，与磁盘文件名分离。PNG 素材另写入 `CanvasFlow.SourceSHA256` iTXt 信息项，表示添加该信息项之前的源文件哈希，避免自引用。JPEG/WebP/GIF 保持原始编码，哈希仍在素材索引记录。
- 原有哈希命名的文件与索引保持兼容，不批量迁移用户现存文件。导入原始素材的 `originals` 命名不变。
- 右键“提取生成所用关键词”严格读取 PNG 元数据的 `prompt` 项，不拼接哈希、项目或任务信息。已验证新增哈希项后的 CRC、中文提示词和项目名保留，以及关键词提取只返回提示词。

旧安装包的卸载行为不会因为源码修改而改变；需要重新构建并分发完整安装包。已经删除的文件也不会自动恢复。
